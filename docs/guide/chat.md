# 群服互通与聊天

群服互通是 LumenBridge 的核心能力：QQ 群消息转发进游戏聊天，玩家聊天与服务器事件推送到群。所有配置都挂在**适配器卡片**的 `sync` 字段下（每个适配器独立一份），详见[连接与适配器](adapters.md)。

## 转发链路总览

```
QQ 群消息 ──→ 适配器 ──→ 群过滤 ──→ 屏蔽词过滤(QQ→游戏) ──→ 格式化 ──→ 截断 ──→ 游戏内广播
玩家聊天 ──→ 聊天吸收探针 ──→ 屏蔽词过滤(游戏→QQ) ──→ 格式化 ──→ 各适配器主群
```

入站消息按**来源适配器**的 `sync` 配置渲染；出站广播按**各适配器各自**的群列表与格式发送（互相独立）。

## QQ 群 → 游戏

监听 `message.group.normal` 事件，处理顺序：

1. **群过滤**：来源群必须在适配器的 `main_group` 列表中（未配置群列表的适配器放行任意群）。
2. **屏蔽词过滤**（QQ→游戏方向）：`block` 模式命中时整条丢弃，`mask` 模式打码后继续。
3. **消息段格式化**：OneBot 消息段数组转为纯文本（见下方格式字段）。
4. **长度截断**：超过 `max_message_length` 时截断并补 `...`（1–4096 字符）。
5. **广播进服**：在主线程执行 `server.broadcast_message`，默认青色（AQUA）显示。

发送者昵称取 `card`（群名片）→ `nickname` → QQ 号的优先级。

## 游戏 → QQ

监听 Endstone 事件并广播到所有**已启用**适配器的群列表：

| 事件 | 开关 | 默认格式 |
|------|------|----------|
| 玩家聊天 | `chat_to_group_enable` | `[玩家] %s: %s` |
| 玩家进服 | `join_to_group_enable` | `[玩家] %s 进服` |
| 玩家退服 | `leave_to_group_enable` | `[玩家] %s 退服` |
| 玩家死亡 | `death_to_group_enable` | `[死亡] %s` |
| 服务器启动 | `server_start_to_group` | `[服务器] 已启动` |
| 服务器关闭 | `server_stop_to_group` | `[服务器] 已关闭` |

单条群消息发送失败只记日志，不中断其余适配器/群的广播。

**广播目标选择**：适配器配置了群列表就发列表里的每个群；未配置时——

- AstrBot：发送到虚拟群 `0`，由 AstrBot 插件端按其 UMO 配置分发
- QQ 官方：发送到运行期**动态发现的群**（机器人收到过消息的群），绝无目标时输出告警

## 聊天转发策略 forward_cancelled

主配置 `chat.forward_cancelled`（详见[配置详解](configuration.md)）决定「被其他插件取消的聊天事件」是否仍转发到群。

背景：聊天美化/格式化插件（如部分 ChatPlus 类插件）会**取消**原生 `PlayerChatEvent`，再把格式化后的文本重新广播展示。对事件系统来说聊天被"取消"了，但玩家确实说了话——直接按"被抑制"处理会导致服聊全部消失。LumenBridge 通过**聊天吸收探针**自动识别这种场景。

### 三种取值

| 取值 | 行为 |
|------|------|
| `auto`（默认） | 取消但消息经广播重发展示 → 转发；无展示证据（禁言/屏蔽词/范围聊天）→ 不转发 |
| `always` | 始终转发。兼容无广播信号的重发型插件（取消后逐玩家 `send_message` 重发、异步重发），代价是被禁言的消息也会转发 |
| `never` | 取消即不转发（最严格） |

### 探针识别原理（auto 模式）

LumenBridge 以 MONITOR 优先级观察两类事件，做**时间戳回溯**关联：

- `BroadcastMessageEvent` 无条件记录 `(消息, 时间戳)` 到最近窗口（默认 1 秒，上限 64 条）
- `PlayerChatEvent`（MONITOR）到达时，若事件被取消，回看窗口内是否存在「包含原始聊天内容」的广播：
  - **强匹配**：广播同时包含玩家名与消息文本 → 美化插件重发，照常转发
  - **弱匹配**：仅包含消息文本（美化广播不含真实玩家名时的兼容路径）→ 照常转发
  - **无匹配** → 消息被管理插件真正抑制（禁言/屏蔽词/范围聊天），不转发

命中的广播条目立即从窗口移除（消费制），同一条广播不会被两轮聊天重复用作证据；该机制与插件注册顺序无关。

已知边界：美化插件把消息文本打散变形（逐字插颜色码）时子串匹配失败，按抑制处理，可改用 `always` 兜底。

## 聊天屏蔽词过滤

双向敏感词过滤，配置存放在 `plugins/lumenbridge/data/chat_filter/words.json`，全部通过 WebUI「聊天过滤」页管理。

### 模式

| 模式 | 行为 |
|------|------|
| `mask`（默认） | 命中词替换为掩码文本（默认 `*`），消息继续转发 |
| `block` | 命中时整条丢弃 |

### 配置项

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | `true` | 总开关 |
| `mode` | `mask` | `mask` / `block` |
| `game_to_qq` | `true` | 游戏→QQ 方向开关 |
| `qq_to_game` | `true` | QQ→游戏方向开关 |
| `mask_text` | `*` | 打码文本 |
| `exempt_players` | `[]` | 玩家名豁免（不区分大小写，游戏→QQ 方向） |
| `exempt_qq` | `[]` | QQ 号豁免（QQ→游戏方向） |

### 词条类型

- **普通词条**（`plain`）：全角→半角 + 大小写归一化后匹配，`ＦＵＣＫ`、`fuck`、`F.u.C.K` 变形词也能命中（变形词本身也要收录为词条）。万级词条合并为分片正则（每片 400 词），匹配性能 O(len(text))。
- **正则词条**（`regex`）：单条长度上限 128，经 ReDoS 风险启发式检查，风险 pattern 直接拒收。

### 词库导入

内置示例词库（`ads.txt`、`profanity.txt`）首次运行自动播种到 `data/chat_filter/wordbanks/`。支持在 WebUI 上传/导入第三方 txt 词库：

- 兼容「每行一词」与「逗号分隔（中英文逗号、顿号、分号）及换行混排」两种格式
- `#` 开头的行为注释
- 导入按归一化形式去重合并，来源标记为词库文件名
