# 白名单绑定

LumenBridge 把 QQ 与 Xbox 玩家名双向绑定，群成员自助完成游戏白名单的申请与移除，退群自动清理。配置在主配置 `whitelist` 节，详见[配置详解](configuration.md#whitelist-白名单)。

## 使用流程

### 绑定

1. 群成员在已绑定的群里发送：

   ```
   绑定白名单 我的Xbox名字
   ```

2. 机器人自动执行游戏命令 `allowlist add 我的Xbox名字`，成功后回复确认并记录绑定关系。

### 解绑

群内发送：

```
解绑白名单
```

机器人执行 `allowlist remove 玩家名`，成功后删除本地绑定记录。

### 退群自动移除

群成员退群时（`notice.group_decrease` 事件），若其有绑定记录且 `remove_on_leave` 开启，自动执行 `allowlist remove` 并在群里公告，移除失败也会公告失败详情。

## 配置项

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `enable` | bool | `true` | 白名单功能总开关（`/lumen reload` 后立即生效） |
| `auto_add` | bool | `true` | 绑定后是否自动执行游戏 `allowlist add`；关闭则只记录绑定关系，不操作游戏白名单 |
| `bind_keyword` | string | `"绑定白名单"` | 触发绑定的消息前缀，绑定名跟在关键词后面 |
| `unbind_keyword` | string | `"解绑白名单"` | 触发解绑的完整消息（整条匹配） |
| `remove_on_leave` | bool | `true` | 玩家退群时自动移除游戏白名单 |

## 双域存储

个人号（QQ 号）与 QQ 官方（openid）身份体系不同，绑定关系**分域存储**：

| 域 | 存储文件 | 身份标识 |
|----|----------|----------|
| 个人号域（`qq`） | `data/whitelist.json` | QQ 号 |
| 官方域（`official`） | `data/whitelist_official.json` | 成员 openid |

同一 QQ 号/openid 在两个域各可绑定一条记录；但 **Xbox 玩家名全域唯一**——同一个玩家名不允许在两个域分别绑定（防止两个 QQ 共用同一游戏身份）。

- QQ 群消息默认进个人号域；QQ 官方机器人产生的事件自动标记 `domain="official"` 进官方域，用户无需关心
- WebUI 白名单页展示合并双域的列表并标注来源

## 数据一致性与安全设计

白名单操作横跨「本地 JSON」与「游戏内命令」两个存储，LumenBridge 用事务式流程保证一致：

- **游戏侧成功才提交本地数据**：绑定/解绑先执行游戏命令，解析命令输出确认成功后，才写入/删除本地记录。避免出现「提示成功但玩家仍在白名单」的错配
- **命令输出识别**：兼容 BDS 新版本本地化 key（`commands.allowlist.add.failed` 等）与旧版本/语言包文本（中英文），识别成功/重复/不存在三种结果。解绑时「玩家本就不在白名单」视为幂等成功
- **pending 互斥**：同一 QQ 或同一 Xbox 名的并发操作会被拒绝（回复「操作进行中」），60 秒超时自愈防止回调丢失把用户永久锁死
- **并发冲突回滚**：极少数并发绑定冲突时，自动回滚刚刚添加的游戏白名单，避免孤儿记录
- **写盘失败回滚**：本地 JSON 写入失败时回滚内存状态，保持内存与磁盘一致
- **损坏自保护**：绑定文件损坏时先备份为 `.corrupt` 再按空列表处理，防止下次落盘把数据永久覆写

## Xbox 玩家名校验

合法字符集：字母、数字、空格、下划线、连字符、点号，1–32 位。名称拼入白名单命令，入口处拒绝非法字符防破坏命令语法；含空格的名称自动加引号包裹。输入外层的引号会被剥除（内部空格保留）。

## WebUI 与 API

WebUI 白名单页支持查看/添加/解绑（合并双域展示）。Web 侧操作使用同步事务 `run_allowlist_command_wait`：等待游戏命令完成（默认 6 秒超时）再返回结果，不阻塞游戏主线程。
